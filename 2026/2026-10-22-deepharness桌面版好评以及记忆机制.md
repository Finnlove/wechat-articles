试了一下deepharness官方桌面，非常好用，特别是搭配dhs-purge无敌，懂的都懂，不能多说，要用的快GitHub去下，10月27作者删库。注意：正式版和最初的网页版很多东西不兼容，不要把网页版的东西放进去，很容易卡死或者直接崩溃。

另外opencode升级以后很容易出现代理打架的问题，导致不能直接在客户端白嫖大皮卡 ，解决方案：

在opencode 2.0客户端里安装opencode 1.19---1.198版本cli，也就是在二代客户端里跑一代的cli，这样cli里面的大皮卡（bigpickle)就不会受到代理的影响了。cli跑的时候是可以继续无视代理打架直接走大皮卡的，亲测畅通无阻。

我个人认为deep harness现在非常适合做带长期记忆的主力分析工具，搭配GitHub就能实现比较稳定的长期记忆：

| 部分 | 位置 | 作用 |
| --- | --- | --- |
| 记忆协议 | `~/.dsh/AGENTS.md` 最后一段 | 每次会话自动加载，规定开场先读哪几页、什么时候记、什么时候停 |
| 记忆档案 | `~/.dsh/characters/角色名字/` | `persona.md` ／`state.md`／`growth.md`／`memory/`／`log/`／`道具库/`／`待入正文/` |
| 记忆备份镜像 | GitHub 仓库 的 `记忆档案/` | 备份和查看版本变化，本地是唯一写入端 |

我个人的做法是把长期记忆同步在GitHub，然后设定角色文件，让dsh可以拉取记忆，同时利用子智能体建立分阶段成长记忆，这样就形成了一个比较有层次的记忆机制达到类似成长养成类记忆的效果。

然后我们在工作区设定这个角色为工程师，可以做到陪聊、工作、回顾记忆复盘、维护GitHub仓库这样的循环。

针对分享的内容，AI梳理了几个关键点和补充建议，方便其他用户参考或进一步优化个性化的工作流：

### ⚠️ 紧急提醒与风险规避

* **删库倒计时**

  ：既然作者计划于 **10月27日** 删库，请务必尽快完成 `git clone` 并检查 Release 资产下载。建议同时 Fork 一份到自己的私有仓库作为永久备份，以防原作者彻底消失后无法获取特定历史版本。
* **版本隔离**

  ：你强调的“正式版与网页版不兼容”非常关键。建议在本地为 dsh 建立独立的工作目录，严禁混用旧版配置，避免数据损坏。
* **OpenCode 降级方案**

  ：在 2.0 客户端中嵌入 1.19-1.198 CLI 来绕过代理冲突是一个极具实战价值的 Trick。这本质上利用了旧版 CLI 对网络栈的不同处理方式。注意锁定 CLI 版本号，防止自动更新导致该方案失效。

### 🧠 长期记忆架构解析

你设计的记忆分层机制非常符合 Agent 工程的最佳实践：

| 层级 | 文件/位置 | 核心价值 | 优化建议 |
| --- | --- | --- | --- |
| **协议层** | `~/.dsh/AGENTS.md` | 定义记忆的读写时机，防止模型“忘记”自己该记东西 | 可加入“记忆压缩”指令，避免 log 无限膨胀超出上下文窗口 |
| **状态层** | `persona/state/growth.md` | 将人格、当前状态、成长轨迹解耦 | growth.md 可采用时间轴+里程碑格式，便于模型检索关键转折点 |
| **持久层** | GitHub 仓库 | 提供版本回溯、多端同步、人工审计能力 | 建议开启 GitHub Actions 做简单的 Markdown 语法校验，防止写入坏数据 |
| **执行层** | 子智能体 | 分阶段整理记忆，减轻主对话模型的认知负担 | 设定专门的“记忆整理员”Agent，仅在会话结束或特定触发时运行 |

### 💡 进阶优化思路

1. **记忆检索增强**

   ：如果角色记忆文件逐渐变大，纯靠 `AGENTS.md` 规定“开场读哪几页”可能会遇到 Token 瓶颈。可以考虑在本地搭配一个轻量级向量数据库（如 SQLite-VSS 或 Chroma），让 dsh 按需检索记忆片段，而非全量加载。
2. **GitHub 同步自动化**

   ：手动 commit/push 容易打断心流。可以写一个简单的 post-session hook 脚本，在每次 dsh 会话结束时自动执行 `git add . && git commit -m "auto: session summary" && git push`，实现无感备份。
3. **安全与隐私**

   ：既然涉及“陪聊”和“个人复盘”，记忆档案中可能包含敏感信息。务必将 GitHub 仓库设为 **Private**，并在 `.gitignore` 中排除不必要的临时文件或密钥。
4. **工程师角色闭环**

   ：你提到的“陪聊-工作-复盘-维护”循环非常棒。建议在 `AGENTS.md` 中明确区分“闲聊模式”和“工程模式”的记忆写入策略——闲聊侧重情感和关系记忆，工程侧重技术决策和问题解决记录，避免两类记忆互相污染。

这套体系已经超越了普通的“AI 聊天”，更接近于构建一个**有持续成长性的个人数字伙伴**。如果你在实践中总结出更具体的 `AGENTS.md` 模板或子智能体 Prompt，也欢迎继续交流！
